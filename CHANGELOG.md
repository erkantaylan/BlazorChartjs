#### [1.0.0](https://github.com/erkantaylan/BlazorChartjs/compare/0.96...1.0.0)

> 10 August 2026

First release of the `Erkan.Blazor.Chartjs` fork, from upstream `0.96`. Targets **.NET 10** and
**Chart.js 4.5.1**. MIT, same as upstream.

##### Fork and packaging

- Published as `Erkan.Blazor.Chartjs`; assembly and root namespace renamed to match. Replace
  `PSC.Blazor.Components.Chartjs` in `_Imports.razor` and in the `_content/...` script paths.
- `TargetFramework` `net8.0` → `net10.0`; all Microsoft packages on 10.0.x.
- Chart.js **3.9.1 → 4.5.1**, chartjs-plugin-zoom **1.2.1 → 2.2.0**, chartjs-plugin-autocolors
  **0.2.2 → 0.3.1**. Bundled chartjs-plugin-annotation **3.1.0** and moment **2.30.1**.
- Removed the stale Chart.js 3.x module chunks and type definitions.
- Demo site for this fork deploys to <https://erkantaylan.github.io/BlazorChartjs/>.

##### Breaking changes

- `Chart.AddData`, `Chart.AddDataset<T>` and `Chart.ClearData` return `Task` instead of being
  `async void`, so they can be awaited and can surface exceptions. `AddData`'s `labels` parameter
  is explicitly nullable.
- `Chart` implements `IAsyncDisposable` instead of `IDisposable`: `Dispose()` removed,
  `DisposeAsync()` added.
- `BarDataset.Stack` is `string?` instead of `List<string>`. `Stack = new List<string> { "One" }`
  becomes `Stack = "One"`.
- `Axis.Text` removed — it serialized as `"Text"`, which Chart.js never read. Use `Axis.Title`.
- `Grid.DrawBorder` removed — Chart.js 4 moved it out of `grid`. Replaced by `Axis.Border`.
- `AxesTime.IsoWeekday` is `int?` instead of `bool?` (0 = Sunday … 6 = Saturday).
- `Zoom.Enabled` removed — chartjs-plugin-zoom 2.x has no master switch, so the property controlled
  nothing. Zoom is turned on per gesture through `ZoomOptions.Wheel`, `ZoomOptions.Pinch` and
  `ZoomOptions.Drag`, and panning through `Zoom.Pan`.

##### Added

- `Axis.Border` — Chart.js 4 axis border (`display`, `width`, `color`, `dash`, `dashOffset`, `z`).
- `Axis.Time` — time-axis configuration (`unit`, `displayFormats`, `tooltipFormat`, `round`, `minUnit`).
- `Plugins.Annotation` — chartjs-plugin-annotation support for lines, boxes, points and labels,
  registered automatically when a chart declares annotations.
- `Options.Locale` — BCP 47 tag propagated to Chart.js and to the moment date adapter.
- Zoom `Limits.X` / `Limits.Y` implemented; `Limits` was previously an empty, unusable class.
- `ZoomOptions.Mode`, `ZoomOptions.OverScaleMode`, `ZoomOptions.ScaleMode`.
- `Chart` event parameters `OnChartClick`, `OnChartOver` and `OnLegendClick` are wired up; they
  were declared upstream but never invoked.

##### Fixed

- Tooltip, title, legend-filter and tick callbacks used synchronous JS→.NET interop, which throws
  on Blazor Server and SSR — including the default .NET 10 Blazor Web App template. They are async
  now and work on every render mode.
- Chart teardown: every chart re-creation leaked a `DotNetObjectReference`, a JS module handle and
  a live Chart.js instance, along with its DOM listeners and queued animation frames.
- `Zoom.Mode` and `Zoom.OverScaleMode` serialized next to the plugin options rather than inside
  them, so chartjs-plugin-zoom never read them and `Mode = "x"` silently did nothing.
- Grouped-stacked bars rendered misaligned because `Stack` was serialized as an array
  ([#48](https://github.com/erossini/BlazorChartjs/issues/48)).
- Legend clicks destroyed Chart.js's built-in dataset show/hide toggle
  ([#89](https://github.com/erossini/BlazorChartjs/issues/89)).
- `RegisterDataLabels` used the process-wide `Chart.register`/`Chart.unregister`, so one chart
  could turn labels off for every other chart on the page
  ([#83](https://github.com/erossini/BlazorChartjs/issues/83)). The plugin is attached per chart now.
- Tooltip callback values were cast to `int`, so `12.5` reached the callback as `12`.
- `Ticks.CallbackAsync` looped forever at 100% CPU, and previously rendered `[object Promise]`.
  Labels are resolved out-of-band, cached per tick, and applied on a single coalesced `update('none')`.
- Axis tick float-noise cleanup rounded to 10 decimal places, zeroing legitimate values below
  `1e-10`. The tolerance is relative to the axis range now: at least 12 significant digits and more
  where the axis resolution needs them, exact integers left alone, and any rounding that would be
  visible at the axis's own resolution refused.
- `AddData` performed a full chart re-render per point; the whole batch is now one round trip and
  one redraw.
- Canvas `Height` and `Width` were both silently dropped when set together (missing CSS semicolon).
- `LegendLabelsFilter`, `TicksCallback`, `TitleCallbacks` and `TooltipCallbacksLabel` threw
  `NotSupportedException` when the property they read was null; they return an empty result now.
- `legend.onClick` is guarded, so charts configured with `Plugins = null` no longer throw a
  `TypeError` during setup.
- `registerDataLabels` was compared instead of deleted (`==` where `delete` was meant), leaving the
  internal flag in the serialized options.
- moment and `chartjs-adapter-moment` are actually shipped and loaded, so `Options.Locale` and time
  axes work at runtime.
- The demo host page loaded `Chart.js` (an ES module) as a classic script, throwing
  `Unexpected token 'export'` on every page load.
